# `doublecheck` Review Guidelines

This document configures automated code review behaviors for Claude Code Review and human reviewers on pull requests in `doublecheck`.

---

## Focus Areas

1. **Child Process Execution & Command Injection:**
   - Never use string interpolation inside shell executors (`execSync`, `exec`).
   - Always use `execFileSync` with discrete, parameterized argument arrays.
   - User-supplied paths, model identifiers, or repository URLs must never be passed to a shell without isolation.

2. **Temporary File & Filesystem Sandboxing:**
   - Never write to predictable filenames in `/tmp` (e.g., `/tmp/temp_${Date.now()}.json`).
   - Use `fs.mkdtempSync` with secure prefixes (`doublecheck-`) and ensure immediate removal in `finally` blocks.
   - Validate finding identity with root-aware canonicalization; display path normalization does not provide OS filesystem containment.

3. **Inference Resilience & Asynchronous Safety:**
   - Network fetches to local Ollama endpoints must use `AbortSignal.timeout(...)`.
   - All async audit runners must be wrapped in `try/catch` blocks inside `orchestrator.js` so that one engine's failure does not crash the entire audit.

4. **Zero Cloud Invariant:**
   - Require explicit matching provider/endpoint routing and opt-in to remote inference. A loopback endpoint alone does not prove local model execution.

---

## Severity Levels

### Blocker (P0)
- Any shell interpolation vulnerability (e.g., `execSync(\`command \${untrusted}\`)`).
- Arbitrary file write or path traversal vulnerabilities.
- Race conditions or uncleaned temporary directories in shared filesystem locations.
- Introducing mandatory external cloud API keys or runtime phone-home behaviors.

### Major (P1)
- Unhandled Promise rejections or omitted `AbortSignal` timeouts on network operations.
- Adding runtime dependencies to `package.json` (the project enforces a zero-runtime-dependency rule).
- New CLI options or agent skill features missing unit test coverage in `tests/`.
- Unmocked subprocess or network calls executed inside the unit test suite.

### Minor (P2)
- Inconsistent JSDoc or markdown formatting in reports or references.
- Stylistic discrepancies not affecting runtime invariants.
- Non-idiomatic ESM imports or exports.

---

## Invariants

- **Runtime Constraints:** Node.js `>= 20.0.0`, ECMAScript Modules (`"type": "module"`).
- **Dependency Boundary:** Only `vitest` is permitted in `devDependencies`. Zero dependencies in `dependencies`.
- **License:** Apache License 2.0 must be preserved across all files.

---

## Ignored Paths

- `dist/**` (compiled distribution outputs generated by `scripts/convert.sh`)
- `node_modules/**`
- `coverage/**`
- `package-lock.json`
